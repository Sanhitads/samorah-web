# Production Environment Variables — Vercel Deployment Checklist

Generated by scanning every `process.env.*` / `NEXT_PUBLIC_*` reference in the codebase.
**40 distinct variables** are referenced.

## ⚠️ Read this first — "Can deployment succeed without it?"

**The Vercel build/deploy step succeeds even if ALL of these are missing.** Next.js does
not validate runtime env at build time — it only inlines `NEXT_PUBLIC_*` (missing → `undefined`)
and runs module-top-level code (none of ours throws on missing env). So the honest answer to
"can deployment succeed without it?" is **Yes for every variable** — the deploy will go green.

**The real risk is runtime.** A missing *required* var means the deploy is live but broken
(DB throws, checkout dead, crons 401). So the column below is **"Runtime impact if missing"**,
which is what actually matters.

## Cron routes — verified present ✅

`vercel.json` schedules three crons; all route files exist with GET+POST handlers, so the jobs
will run (each guarded by `CRON_SECRET`, which Vercel Cron sends as `Authorization: Bearer`):

- `src/app/api/cron/fulfillment/route.ts` → `/api/cron/fulfillment` (`*/5 * * * *`)
- `src/app/api/cron/reservations/route.ts` → `/api/cron/reservations` (`*/5 * * * *`)
- `src/app/api/cron/retention/route.ts` → `/api/cron/retention` (`0 3 * * *`)

## 1. REQUIRED — app is broken at runtime without these

| Name | Scope | Source | Runtime impact if missing |
|---|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | Public | Supabase → Project Settings → API | **All data + auth dead.** Browser + server clients fail. |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Public | Supabase → API keys (anon) | **Auth/storefront reads fail** (client throws). |
| `SUPABASE_SERVICE_ROLE_KEY` | Server | Supabase → API keys (service_role) | **Every admin/server DB op throws** (orders, admin, all crons). `createAdminClient()` throws. |
| `NEXT_PUBLIC_RAZORPAY_KEY_ID` | Public | Razorpay → Settings → API Keys | **Checkout can't open Razorpay** → no payments. |
| `RAZORPAY_KEY_SECRET` | Server | Razorpay → API Keys | **No payment verify / refunds / settlements.** `RAZORPAY.configured` = false. |
| `RAZORPAY_WEBHOOK_SECRET` | Server | Razorpay → Webhooks | Webhook signature check fails → orders rely only on `/verify` (fragile). |
| `CRON_SECRET` | Server | You generate (random string) | **All 3 crons return 401** → fulfillment/reservations/retention never run. |
| `RESEND_API_KEY` | Server | Resend → API Keys | **All transactional emails fail** (order confirmation, dispatch, etc.). |
| `NEXT_PUBLIC_CLOUDINARY_CLOUD_NAME` | Public | Cloudinary → Dashboard | Media/images don't render or upload. |
| `CLOUDINARY_API_KEY` | Server | Cloudinary → Dashboard | Admin media **upload** fails. |
| `CLOUDINARY_API_SECRET` | Server | Cloudinary → Dashboard | Admin media **upload** fails (signature). |

## 2. RECOMMENDED — has a fallback, but set explicitly in production

| Name | Scope | Source | Fallback / impact if missing |
|---|---|---|---|
| `ORDER_TOKEN_SECRET` | Server | You generate (random 32+ chars) | Falls back to `RAZORPAY_KEY_SECRET` → dev default. **Set a dedicated random secret** for order-link signing. |
| `IP_HASH_SALT` | Server | You generate (random) | Falls back to `SUPABASE_SERVICE_ROLE_KEY` → `"samorah-ip-salt"`. Set for stable, private IP hashing. |
| `NEXT_PUBLIC_SITE_DOMAIN` | Public | Your domain, e.g. `samorahstudio.com` | Defaults to `samorahstudio.com`. **Set to your real domain** — drives canonical URLs / OG / sitemap / SEO. |
| `EMAIL_FROM` | Server | Your verified sender address | Emails may fail or use a default sender. Set to your verified Resend domain sender. |
| `EMAIL_REPLY_TO` | Server | Your reply-to address | Optional; improves replies. |

## 5. OPTIONAL — GA4 Data API (live users + conversion in admin)

Keyless via Workload Identity Federation (recommended). All no-op until set.

| Name | Scope | Source | Notes |
|---|---|---|---|
| `GA4_PROPERTY_ID` | Server | GA4 → Property Settings (numeric) | Required for any GA4 Data API read. |
| `GCP_WORKLOAD_IDENTITY_AUDIENCE` | Server | GCP WIF pool/provider | `//iam.googleapis.com/projects/<num>/locations/global/workloadIdentityPools/<pool>/providers/<provider>` |

## 6. AUTO-MANAGED by Vercel — do NOT set manually

| Name | Notes |
|---|---|
| `NODE_ENV` | Vercel sets `production` automatically. |
| `VERCEL_OIDC_TOKEN` | Injected by Vercel when OIDC Federation is enabled (Builds env / `x-vercel-oidc-token` header in Functions). Enable the toggle in Project → Settings → Security; never set by hand. |
